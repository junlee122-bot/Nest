# 둥지(Nest) 심사 데모 스크립트

발표·시연에서 그대로 따라 할 수 있는 순서와 멘트, 예상 질문 답변을 정리한 문서입니다.

## 준비

- 배포 URL(예: https://nest-jv3h.vercel.app) 또는 `npm run dev` 로컬 서버
- 데모 시작 화면: `/showcase?present=1` (발표자 모드 자동 진입)
- 발표자 모드 조작: `←` `→` 단계 이동 · `Esc` 종료 · 하단 바에 현재 발표 멘트 표시
- 키 없이 시연할 경우: AI 기능은 **예시로 둘러보기** 버튼이 전체 흐름을 대신 보여주고,
  **에어컨 요금 계산은 키·네트워크와 무관하게 항상 실계산**으로 동작

시간이 남으면 실제 앱으로 이동:
1. `/utility` — 벽걸이·6평·6시간을 고르면 **제출 버튼 없이 즉시** "약 12,000원"이 나오고,
   슬라이더를 움직일 때마다 재계산되는 것을 보여줌 (심사위원이 직접 만져보게 하기 좋음)
2. `/utility` 고급 설정 아래 "내 에어컨 사진으로 정확도 높이기" → 모델명 검색 →
   실제 제품 썸네일 후보 → "내 에어컨이 맞아요" → 종류 자동 반영 + 확인 배지
3. `/repair` 예시 결과(오늘 할 일·집주인 문구·증거 기록), `/grocery` 예시(가격 출처 배지)

## 사용할 예시 입력

- 집수리: "천장에서 물이 떨어지고 벽지가 젖었어요." (+ 누수 사진 1장)
- 계약서: 입력창의 **예시 계약서 채우기** 버튼 또는
  "임차인은 모든 수선비를 부담하며, 보증금 반환은 신규 임차인 입주 후로 한다."
- 에어컨 요금: 벽걸이형 · 6평 · 하루 6시간 (7월 기준 약 12,000원, 범위 7,000~32,000원)
- 내 에어컨 찾기: 제조사 "삼성" + 모델번호 "AR07C9150HZS" (실존 벽걸이 7평 모델 —
  완전 일치 후보 3개가 썸네일과 함께 나옴)
- 장보기: 예산 "3만 5천원", 기간 7일, 점심·저녁 / 남은 재료 "계란, 두부, 대파, 김치"
- 시세: 주소 검색으로 아무 동네나 선택 → 단독·다가구(원룸)

## 예상 질문과 답변

**Q. 법률 자문인가요?**
A. 아닙니다. 참고용 안내이며, 화면마다 고지합니다. 위험 상황에서는 공인중개사,
주택임대차분쟁조정위원회, 변호사 상담을 권장하도록 설계했습니다.

**Q. 에어컨 요금도 AI가 계산하나요?**
A. 아닙니다. 요금은 한전 주택용 요금표(하계/기타 누진, 저압/고압, 슈퍼유저, 기후환경·
연료비조정·부가세·기금)를 그대로 구현한 **순수 계산 함수**가 브라우저 안에서 계산합니다.
같은 입력에는 언제나 같은 답이 나오고, 정확값 6케이스를 포함한 단위 테스트 55개로 검증하며,
계산 중 네트워크 요청이 0회입니다. AI(Vision)는 라벨 사진에서 모델번호·소비전력을 "읽는"
데만 쓰고, 숫자 계산에는 관여하지 않습니다.

**Q. 제품 검색으로 찾은 에어컨을 그냥 믿어버리나요?**
A. 아닙니다. 후보가 하나뿐이어도 자동 확정하지 않고, 사용자가 "내 에어컨이 맞아요"를
눌러야 적용됩니다. 라벨 판독도 "라벨에서 OOO로 읽었어요"라고만 말하고 흐리면 수정을
요청합니다. 모델 확인과 소비전력 검증은 별도 배지로 구분해, 사진이 일치한다고 해서
소비전력이 검증된 것처럼 보이지 않게 했습니다.

**Q. 사진이나 계약서를 저장하나요?**
A. 저장하지 않습니다. 서버 처리 후 영구 저장하지 않으며, 최근 기록도 민감한 원문이 아니라
이 기기의 localStorage 요약만 사용합니다. 서버 로그에도 사용자 원문을 남기지 않습니다.
에어컨 라벨 사진은 브라우저에서 리사이즈하며 EXIF를 제거하고, 시리얼 번호는 프롬프트
금지와 서버측 마스킹으로 이중 차단합니다.

**Q. API 키가 없으면 어떻게 되나요?**
A. 핵심 UI는 폴백 데이터로 동작하고, 키가 있으면 공공데이터와 이미지가 보강됩니다.
화면에 "오늘 시세/참고가/예시 데이터" 같은 출처 배지로 상태를 정직하게 표시합니다.
에어컨 요금 계산은 키와 무관하게 항상 실계산입니다.

**Q. 그냥 챗봇과 무엇이 다른가요?**
A. 두 가지입니다. 첫째, 사진/계약서/시세/장보기 데이터를 "판단 → 근거 → 행동" 카드로
바꿉니다. 둘째, **AI가 잘하는 일과 못하는 일을 구분**합니다 — 이해·판독은 AI에게,
요금 같은 숫자 계산은 검증된 결정론 엔진에게 맡깁니다. AI 출력 스키마와 서버가 부착하는
데이터 필드를 분리해, 모델이 형식을 어겨도 데이터 레이어가 깨지지 않는 구조입니다.

**Q. 금융 기능은 실계좌인가요?**
A. 아닙니다. 금융결제원 오픈뱅킹 **테스트베드 모의계좌** 기반 PoC이며 화면에 명시합니다.

## 기술적 차별점 (질문 대비)

- **역할 분리 아키텍처**: 이해·판독 = AI(Claude Vision), 숫자 = 결정론 엔진(lib/electricity),
  근거 = 공공데이터·룰북. AI가 요금을 "지어내는" 경로가 구조적으로 없음
- 한전 요금 엔진: 정확값 6케이스·누진 경계·슈퍼유저·불변식 등 단위 테스트 55개,
  요금표는 단일 파일 스냅샷(확인일 표기)이라 개정 시 한 곳만 갱신
- 냉방능력 W ≠ 소비전력 W 교차 가드 — Vision이 능력값을 소비전력에 잘못 넣으면 서버가 기각
- AI 스키마와 서버 부착 데이터의 분리 (모델 드리프트에 안전)
- 공공데이터 6종+ 연동, 전부 무키 폴백으로 데모가 깨지지 않음
- balanced-brace JSON 파서 + 스키마 검증 + 1회 교정 재시도
- 버킷별 레이트리밋(비전 더 엄격), 이미지 서버측 이중 검증, 시리얼 마스킹, 보안 헤더
- prefers-reduced-motion 존중, 네이티브 radio 기반 키보드 조작, aria 패턴 적용

## 디자인적 차별점

- "민트 가든" 톤 + 둥이 마스코트는 홈·로딩·빈 상태에만, 법률·금융 화면은 신뢰 우선
- 정보 위계: 판단(히어로) → 행동(카드) → 근거(접힘) 순서 고정
- 위험도·가격 출처를 색과 텍스트로 함께 표시 (색상만으로 전달하지 않음)
- 숫자는 과신을 막도록 표시: 추정 금액은 1,000원 단위 반올림 + "추정치" 배지 + 낮음~높음 범위
