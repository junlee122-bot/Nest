# 둥지(Nest) 심사 데모 스크립트

발표·시연에서 그대로 따라 할 수 있는 순서와 멘트, 예상 질문 답변을 정리한 문서입니다.

## 준비

- 배포 URL 또는 `npm run dev` 로컬 서버
- 데모 시작 화면: `/showcase?present=1` (발표자 모드 자동 진입)
- 발표자 모드 조작: `←` `→` 단계 이동 · `Esc` 종료 · 하단 바에 현재 발표 멘트 표시
- 키 없이 시연할 경우: 각 기능의 **예시로 둘러보기** 버튼이 전체 흐름을 대신 보여줌

## 90초 발표 순서

| 시간 | 화면 | 클릭 | 멘트 |
| --- | --- | --- | --- |
| 0~10초 | /showcase 히어로 | `90초 데모 시작` | "둥지는 혼자 사는 사람이 집 문제를 만났을 때 가장 먼저 켜는 AI 주거 생활 도우미입니다." |
| 10~30초 | 목업: 집수리 시나리오 | (자동 진행) | "누수 사진이나 설명을 넣으면 긴급도, 응급처치, 책임 가능성, 집주인에게 보낼 문장을 한 번에 정리합니다." |
| 30~50초 | 목업: 계약서 시나리오 | (자동 진행) | "계약서 특약은 위험 문구를 하이라이트하고, 왜 위험할 수 있는지와 수정 요청 문구를 보여줍니다." |
| 50~70초 | 목업: 장보기·시세 | (자동 진행) | "월세는 실거래가 기준으로 비교하고, 장보기는 시세·제철·보관·음식 이미지 API까지 붙여 생활비 문제로 확장했습니다." |
| 70~90초 | Data 섹션 스크롤 | 신호 카드 1~2개 클릭 | "핵심은 AI 답변을 길게 보여주는 것이 아니라, 사용자가 바로 할 수 있는 행동 카드로 바꾸는 것입니다. 카드마다 데이터 출처와 무키 폴백까지 정직하게 표시합니다." |

시간이 남으면: 실제 앱으로 이동해 `/repair` 예시 결과(오늘 할 일·집주인 문구·증거 기록)와
`/grocery` 예시(가격 출처 배지·먼저 먹을 순서)를 보여줍니다.

## 사용할 예시 입력

- 집수리: "천장에서 물이 떨어지고 벽지가 젖었어요." (+ 누수 사진 1장)
- 계약서: 입력창의 **예시 계약서 채우기** 버튼 또는
  "임차인은 모든 수선비를 부담하며, 보증금 반환은 신규 임차인 입주 후로 한다."
- 장보기: 예산 "3만 5천원", 기간 7일, 점심·저녁 / 남은 재료 "계란, 두부, 대파, 김치"
- 시세: 주소 검색으로 아무 동네나 선택 → 단독·다가구(원룸)

## API 키가 있을 때 / 없을 때

| 기능 | 키 있음 | 키 없음 (폴백) |
| --- | --- | --- |
| 수리·계약서·장보기 AI | 실제 분석 결과 | "예시로 둘러보기"가 전체 흐름 시연 |
| KAMIS 오늘 시세 | 항목별 "오늘 시세" 배지 | 내장 참고가격표 ("참고가" 배지) |
| Pexels 음식 이미지 | 사진 카드 + 크레딧 | 텍스트 카드 |
| 식약처 레시피 | "공공 레시피로 더 해먹기" 섹션 | 섹션 생략 (에러 없음) |
| RTMS 실거래가 | 실제 신고 데이터 + 조회 월 | "예시 데이터" 명시 화면 |
| Kakao 주변 업체 | 업체 미리보기 | 지도 검색 링크 |
| 오픈뱅킹 | 테스트베드 모의 분석 | "베타 준비중" 안내 |

## 예상 질문과 답변

**Q. 법률 자문인가요?**
A. 아닙니다. 참고용 안내이며, 화면마다 고지합니다. 위험 상황에서는 공인중개사,
주택임대차분쟁조정위원회, 변호사 상담을 권장하도록 설계했습니다.

**Q. 사진이나 계약서를 저장하나요?**
A. 저장하지 않습니다. 서버 처리 후 영구 저장하지 않으며, 최근 기록도 민감한 원문이 아니라
이 기기의 localStorage 요약만 사용합니다. 서버 로그에도 사용자 원문을 남기지 않습니다.

**Q. API 키가 없으면 어떻게 되나요?**
A. 핵심 UI는 폴백 데이터로 동작하고, 키가 있으면 공공데이터와 이미지가 보강됩니다.
화면에 "오늘 시세/참고가/예시 데이터" 같은 출처 배지로 상태를 정직하게 표시합니다.

**Q. 그냥 챗봇과 무엇이 다른가요?**
A. 사진/계약서/시세/장보기 데이터를 "판단 → 근거 → 행동" 카드로 바꾸는 점입니다.
AI 출력 스키마와 서버가 부착하는 데이터 필드를 분리해, 모델이 형식을 어겨도
데이터 레이어가 깨지지 않는 구조입니다.

**Q. 금융 기능은 실계좌인가요?**
A. 아닙니다. 금융결제원 오픈뱅킹 **테스트베드 모의계좌** 기반 PoC이며 화면에 명시합니다.

## 기술적 차별점 (질문 대비)

- AI 스키마와 서버 부착 데이터의 분리 (모델 드리프트에 안전)
- 공공데이터 6종+ 연동, 전부 무키 폴백으로 데모가 깨지지 않음
- balanced-brace JSON 파서 + 스키마 검증 + 1회 교정 재시도
- 버킷별 레이트리밋, 이미지 서버측 이중 검증, 보안 헤더
- prefers-reduced-motion 존중, aria 패턴 적용

## 디자인적 차별점

- "민트 가든" 톤 + 둥이 마스코트는 홈·로딩·빈 상태에만, 법률·금융 화면은 신뢰 우선
- 정보 위계: 판단(히어로) → 행동(카드) → 근거(접힘) 순서 고정
- 위험도·가격 출처를 색과 텍스트로 함께 표시 (색상만으로 전달하지 않음)
